# 启动和预览网页

使用现有 `jingjiaagent` MCP 提供的工具；执行器显示的名称可能带 `jingjiaagent_` 或 `mcp__jingjiaagent__` 前缀。技能只是流程说明，实际后台终端与端口映射由平台工具完成。

1. 阅读项目说明、依赖锁文件和已有启动配置。调用 `background_terminal_list`，并用现有 Shell 检查监听端口，优先复用已运行且属于本任务的服务，不重复启动。
2. 使用 `background_terminal_create(command=..., cwd=..., request_id=...)` 启动长期运行的服务。工作目录必须位于 `/workspace`；命令以前台方式运行，不追加 `&`、`nohup`、`setsid` 或另建守护进程。工具负责后台会话。
3. 同一次启动重试使用同一 `request_id`，例如 `website-8000-start-1`。返回已退出会话时先查看日志；只有明确重新启动时才使用新的 ID。同一 ID 不能改为其他命令。
4. 调用 `background_terminal_output_path(terminal_id=...)` 获得日志路径，再用现有 Shell 的 `tail` 等命令读取。日志按大小轮转，必要时查看 `.1` 文件。日志位于受管理运行目录，不放入成果目录。
5. 确认服务监听并返回 HTTP 响应。员工打开高级工具的预览面板后，平台自动发现运行中的 HTTP 服务，可直接点击“访问”；普通 Shell 启动的 HTTP 服务也能被发现，无需先调用工具登记。
6. 需要在回复中提供链接时调用 `request_preview(port=...)`。工具不会启动网站，只为当前任务的服务创建或复用域名路由。必须使用工具返回的 `access_url`，不要根据工作空间 IP、宿主机地址或内部端口自行猜测链接。服务发现本身不开放访问，点击“访问”或调用此工具才创建路由。
7. 新路由默认公开，免平台登录；员工可在预览面板中限制访问 IP 或关闭访问。保留已有的访问策略：工具不会自动重新开放员工已关闭的路由，也不会替换其白名单。路由已关闭时，请员工在预览面板中重新开放；不要尝试通过其他端口绕过关闭设置。管理员未配置预览域名时，说明需要配置域名，不能自行使用公共 DNS 服务。

## 常见启动方式

- 静态文件：`python3 -m http.server 8000 --bind 0.0.0.0`，`cwd` 指向需要服务的目录，避免无意公开整个仓库。
- Vite：按项目定义执行 `npm run dev -- --host 0.0.0.0`。设置需要的允许主机和 WebSocket 外部地址，尤其是 HTTPS 网关；不要为了排错一律关闭主机检查。
- 其他 HTTP 应用：采用仓库既定命令与端口，检查日志和 HTTP 状态。平台保护的内部端口不可用于应用预览。

Node/npm、pnpm 和 Python 已随镜像提供，但任意项目依赖并不保证已经缓存。离线环境只能使用已有依赖、完整缓存或管理员提供的内部软件源。缺包时说明缺失项，不默认下载外部模板、技能或依赖。

## 排错和停止

- 区分服务未启动、应用返回 401/404/500、白名单拒绝、环境休眠和平台代理异常。401/404/500 仍会作为 HTTP 服务显示，不等于页面正确。网络超时、正在保存等暂时无法确认的状态，不应判断为服务已经停止。没有真实响应检查时，不声称网站验证通过。
- 工具响应超时先查询已有会话并使用相同启动 ID 重试，防止同一命令重复运行。
- `background_terminal_kill(terminal_id=...)` 只停止指定受管理会话及其会话内子进程，不使用宽泛的 `pkill node` 等命令。关闭预览访问与停止服务是两个不同操作。
- 本轮回答结束、任务被中断或员工关闭浏览器不会主动停止服务；服务仍运行时继续出现在预览列表。服务确认停止或工作空间休眠、停止、回收后，条目消失。恢复文件不等于恢复进程；员工通过正常续聊要求恢复并启动服务后，重新检测并按需要启动，不自动重放旧命令。相同任务与内部端口复用原域名。
- 网页源代码保留在项目目录；用户要求交付的静态包或报告可放在 `/workspace/.jingjiaagent/output`。后台日志、临时文件不得作为正式成果登记。

平台支持外部 HTTP／HTTPS 访问工作空间的 HTTP 服务，不支持发布 Redis、任意 TCP 或工作空间 HTTPS 上游。HTTP 预览支持普通网页，不保证摄像头、Service Worker 等安全上下文功能。需要这些功能时说明需要可信 HTTPS 配置。预览是临时访问入口，不承诺永久发布或永久链接；访问旧链接不会唤醒工作空间或触发 AI。
