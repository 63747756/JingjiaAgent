日期：2026-10-05。基线：`539d13d115061630b0e475fb65a72f7cf1118057`。
修复工作区分支：`codex/runtime-deployment-fixes`。本报告记录该基线上的修复增量。验收结束时尚未提交或发布；后续提交、推送和合并状态以 Git 记录为准。

## 结论

上一轮确认的三项部署阻断／运行配置问题已经修复，并在全新的独立环境通过复测：

1. MinIO 留在隔离业务网络；浏览器通过原 Web 的 `/oss/` 入口上传和下载，不再发布原始存储或控制台端口。
2. 私有文本文件统一写 LF；启动前验证 Redis secret 的实际字节，Redis、后端及健康检查使用同一密码。
3. Claude 每轮启动前原子同步 settings 中的平台模型字段，保留其他环境、权限和插件设置；LLM-only 更新后不再被旧 settings 覆盖。

同时补齐了迁移检查对停止状态 Guest 的检查。实际运行及停止的旧网 Guest 均能被拒绝，检查不会自行改变网络。

本轮没有手工规范化 Redis 密码文件，没有添加临时存储代理，也没有在 Claude 对照试验中删除旧 settings。
三项原有阻断在本机范围内已解除；尚未覆盖的部署场景见最后一节。

## 部署及验收边界

这些结果是本机独立环境的实测，不代表独立 Linux 服务器、多节点、长时间多用户负载或生产迁移验收完成。
本轮没有补齐外部可写 Git 仓库、外部 MCP 工具执行及完整 Skills／插件选择超时部署验收；此前报告中的相应边界继续有效。
没有重新把上一轮所有测试计为本轮实测，例如 SSE 丢增量和后端 SIGKILL 的既有通过记录仍属于上一轮。

部署必须使用新构建的 p23 Guest。已有 Sandbox 不会随默认镜像更新自动升级，不能把重启旧 p22 当成该修复已经生效。
旧环境迁移仍需维护窗口、任务及文件备份、归属核对和受控迁移，不能删除数据卷或跨后端重放任务。

本轮测试环境在验收收尾时停止，保留数据卷、镜像和证据；原部署未改动。验收收尾时没有提交、合并或推送代码，后续状态以 Git 记录为准。
