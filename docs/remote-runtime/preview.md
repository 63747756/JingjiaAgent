# 工作空间网页预览

预览复用 agent-compose、后台终端、平台 MCP 和共享 Nginx 网关，只使用独立域名。AI 负责启动应用；平台发现运行中的 HTTP 服务，并在员工访问或 AI 请求地址时创建路由。新路由默认公开、免平台登录，员工可以限制 IP 或关闭访问。

## 使用流程

打开任务的「高级工具 → 预览」即可看到正在运行的网页服务，不要求预先调用 `request_preview`，也不需要填写端口。点击「访问」检查服务并创建或复用地址，在新标签页打开。更多菜单支持复制地址、公开／限制 IP 和关闭访问。关闭访问但仍运行的服务保留在列表中，员工可明确选择「重新开放并访问」。

HTTP 首页返回 401、404 或 500 仍算网页服务。Redis、自定义 TCP 和平台内部监听端口不进入列表。面板与浏览器标签页可见时每 10 秒查询当前任务；隐藏后停止轮询。同一工作空间发现请求合并并短暂缓存约 5 秒，权限撤销不受发现缓存影响。

| 情况 | 预览列表 |
|---|---|
| HTTP 服务运行，AI 回答结束或被中断 | 继续显示 |
| 成功扫描确认服务停止 | 移除条目，保留域名路由 |
| 工作空间休眠、停止或回收 | 空状态 |
| 网络异常、超时、保存／恢复中 | 暂时无法确认，不误报没有服务 |
| 未配置预览域名 | 提示管理员配置，不提供访问 |

访问旧链接不会唤醒环境或调用 AI。需要恢复工作空间、启动应用时，通过正常续聊告诉助手处理。恢复文件不等于恢复进程，不会自动重放旧命令。

## AI 工具与技能

OpenCode、Codex、Claude 通过现有任务鉴权 MCP 共用：

| 工具 | 用途 |
|---|---|
| `background_terminal_create` | 在 `/workspace` 内启动后台会话；同次重试复用 `request_id` |
| `background_terminal_list` | 查询本任务托管会话 |
| `background_terminal_output_path` | 返回日志路径，由 Shell 读取；日志限额并轮转 |
| `background_terminal_kill` | 精确停止会话及子进程 |
| `request_preview` | 验证 HTTP 服务，创建或复用域名；不启动服务，不重新开放员工关闭的路由 |

本地打包的 `deploy-website` 指导 AI 检查已有服务、启动后台命令、看日志并确认 HTTP 可访问；需要在回复中提供链接时调用 `request_preview`。员工也可直接在面板访问。普通 Shell 启动的 HTTP 服务同样可发现，但不会自动纳入托管终端列表。

回合结束、关闭页面和自动保存不额外停止服务。工作空间的休眠、回收继续由管理员任务策略控制。预览窗口不另设全局扫描或回收定时任务。

## 地址与生命周期

```text
随机标识.preview.example.internal
    → 当前任务的工作空间
    → 服务内部端口
```

同一任务、同一端口复用同一域名。服务停止隐藏条目但保留记录；恢复到新实例时原子切换路由目标，保留访问设置与关闭状态。任务删除撤销路由和已有连接，随机标识不分配给其他任务。没有外部端口池、空闲端口分配或冷却回收逻辑。

外部支持 HTTP 或 HTTPS，HTTPS 在网关终止，上游工作空间应用使用 HTTP。支持网页静态资源、流式响应与 WebSocket；不提供 Redis／任意 TCP 发布，也不支持工作空间 HTTPS 上游。多宿主机共用一个网关入口。

## 部署

完整参数见[安装器文档](../../installer/README.md#预览地址与访问控制)。未配置 `--preview-url` 默认关闭预览，平台其他功能正常。配置域名 URL 自动启用：

```sh
sudo ./install.sh --public-url https://agent.example.internal \
  --preview-url http://preview.example.internal

sudo ./jingjiaagent configure-preview --root /opt/jingjiaagent \
  --preview-url https://preview.example.internal \
  --preview-tls-cert fullchain.pem --preview-tls-key preview.key --ca-cert company-ca.pem
```

基域 `preview.example.internal` 与 `*.preview.example.internal` 均需通过企业 DNS 指向网关，员工电脑和部署机均需能解析并访问。HTTPS 证书覆盖基域与通配子域，客户端信任签发机构；HTTP 无需预览证书。只开放统一网关入口，不开放一段任务端口。后台监听保持私有。

安装前检查 DNS，安装完成与 `doctor` 对基域和随机子域检查真实 DNS、HTTP／TLS 链路。员工端网络和信任另行验证；指定 Host 的模拟检查不能代替真实 DNS 验收。在线离线包使用相同配置逻辑。

旧 IP 模式升级前必须提供域名或显式 `--preview-mode off`，校验在停止现有服务前执行。旧 IP 链接不兼容，任务、文件及成果保留。配置修改失败恢复原配置；升级保留完整备份。

## 访问边界

- 扫描只发现服务，不发布。员工访问或 AI 请求后才建立路由，新路由公开，旧路由保留原权限。
- 限制 IP 模式只允许名单中的客户端，空名单拒绝全部。关闭访问拒绝所有请求，刷新、恢复及 AI 请求不会擅自重新开放。
- 当前 IP 使用当前可信连接；不信任访客自行提交的转发头。企业代理需明确信任来源，共用 NAT 时不能单凭 IP 区分员工。
- 关闭访问、修改白名单及删除任务会撤销已有长连接；发现结果缓存不缓存权限判断。
- 保留 Cookie 过滤、Origin 校验、内部端口保护和工作空间所有权校验。
- 服务停止期间，旧链接返回「预览暂不可用」，不触发恢复或 AI 执行。

## 验证范围

回归覆盖后台 HTTP 发现、缓存合并、路由和权限、前端可见性轮询、安装配置、DNS、证书和回滚。后台终端、MCP 鉴权及其他部署回归继续保留。

隔离 Docker 与虚拟机验收分别记录：普通 Shell 服务自动出现，Redis 排除、Java HTTP，AI 中断与实际服务停止，休眠恢复同域名，暂时错误，关闭／重新开放与权限撤销，重复请求，HTTP／HTTPS／WebSocket／静态资源，以及在线、离线、配置和升级前检查。模拟 DNS／Host 测试与员工可达的真实 DNS 验收必须分开记录。
