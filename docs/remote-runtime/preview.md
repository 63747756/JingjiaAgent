# 工作空间网页预览

预览复用 agent-compose、PTY 后台会话、平台 MCP 和共享 Nginx 网关。AI 启动应用，平台为已运行的 HTTP 服务分配访问地址。网页免平台登录，访问仍受 IP 白名单限制。

本页描述当前实现。历史验收中的登录跳转、一次性票据和预览授权 Cookie 属于已移除的旧方案，不能作为当前功能的验收依据。

## 使用流程

在助手的「助手内置技能」中选择本地 `deploy-website`。新建助手默认预选，已有配置不会被覆盖。AI 检查项目和已有服务、启动后台命令、读取日志并验证响应，再调用 `request_preview(port=8000)`。地址同步出现在任务「高级工具 → 预览」，可打开、复制、关闭访问、修改白名单。网页在新标签页打开，不提供内嵌浏览器或浏览器自动操作。

## 工具和生命周期

OpenCode、Codex、Claude 通过已有的已鉴权 MCP 共用以下工具：

| 工具 | 用途 |
|---|---|
| `background_terminal_create` | 在 `/workspace` 内启动后台会话；同次重试复用 `request_id` |
| `background_terminal_list` | 查询本任务托管的会话 |
| `background_terminal_output_path` | 返回日志路径，由现有 Shell 读取；日志限制大小并轮转 |
| `background_terminal_kill` | 精确停止对应会话及子进程 |
| `request_preview` | 检查已有 HTTP 服务，申请或复用映射；不会启动服务 |

工具凭证绑定任务和员工，不能操作其他任务。普通 Shell 启动的 HTTP 服务也可发现和开放，但不会自动纳入后台会话列表。平台内部监听端口不可开放。申请映射只更新记录，不逐次重建网关或容器。

回合结束、关闭页面和自动保存工作区不会额外停止服务。关闭预览仅撤销访问；工作空间按任务策略停止或回收后，服务随之停止。恢复文件不代表恢复进程：重新检查并按需要启动，不自动重放旧命令。

## 地址与部署

完整参数、证书和回滚说明见[安装器文档](../../installer/README.md#预览地址与访问控制)。

| 模式 | 示例 | 要求 |
|---|---|---|
| IP＋HTTP | `http://192.168.1.20:31000` | 员工可达 IP、开放端口池 |
| IP＋HTTPS | `https://192.168.1.20:31000` | 证书包含对应 IP SAN，客户端信任签发机构 |
| 域名＋HTTP | `http://随机标识.preview.example.internal` | 通配 DNS 指向网关 |
| 域名＋HTTPS | `https://随机标识.preview.example.internal` | 通配 DNS 和对应证书 |

新安装默认端口模式，端口池 `31000–31099`，协议默认沿用控制台，也可单独指定。端口模式 `--preview-url` 不含端口；控制台用域名时明确提供预览 IP，或选择域名模式。域名模式使用独立预览域，不能覆盖平台入口。

HTTPS 在网关终止，工作空间应用可使用 HTTP；内部节点通信保持 HTTPS。HTTPS 控制台打开 HTTP 预览使用新标签页。HTTP 不保证摄像头、Service Worker 等安全上下文能力，HTTP 域名需避开父域 HSTS 强制升级。

网关统一发布端口池，后台预览监听保持私有。平台查询映射后，经节点认证通道到达工作空间，多宿主机复用同一入口。端口池容量与任务并发数独立。

任务预览按「任务＋服务端口」保留地址。关闭访问、休眠、停止或回收工作空间都不释放地址；任务恢复到新工作空间时，映射 ID、外部端口、白名单和关闭状态保持原样。后台在恢复提交的同一事务内切换映射指向，旧工作空间不能再申请或继续提供该任务的预览。恢复文件不会启动进程，需要在新工作空间重新启动原服务端口；员工已关闭的预览不会因恢复而自动开放，空白名单仍拒绝所有访问。

只有真正删除任务（软删除或物理删除）才关闭其映射并开始 24 小时冷却。非任务开发环境的映射仍在环境删除时开始冷却。冷却结束后的端口可能被后续分配，不作为永久分享地址。

升级迁移从运行时任务意图、执行命令中识别旧映射归属。一个任务的同一服务端口已有多代记录时，优先保留当前任务工作空间的映射，否则采用创建时间最新的记录（时间相同按 ID 确定）；其他历史记录保留原白名单用于追溯，但关闭并进入冷却。旧实现已回收并再次分配的端口不会抢回；原记录的端口已清空时，下一次申请会分配可用地址。旧版本已经关闭的记录不会在迁移时被猜测为开放状态。发现同一工作空间对应多个任务的异常关系时停止迁移并提示修复，不猜测归属。

已有安装先升级，在没有执行或排队任务时重配置：

```bash
sudo /opt/jingjiaagent/jingjiaagent configure-preview \
  --root /opt/jingjiaagent \
  --preview-mode port \
  --preview-url http://192.168.1.20 \
  --preview-port-range 31000-31099
```

普通升级保留原配置；重配置执行预检查、备份、应用和健康检查，失败回滚。安装器提示防火墙要求，不直接修改宿主机防火墙。在线和离线包携带相同工具、技能；业务依赖仍需完整缓存或内网软件源。

## 访问边界

- 创建、关闭映射和修改白名单需要任务权限；匿名访问检查映射、环境状态、任务权限及客户端 IP。
- 首次开放使用后台从任务所属员工的登录请求中确认的 IP。缺少可信 IP 时保持关闭，空白名单拒绝访问。
- 不信任访客自行提交的转发头。企业代理需明确配置可信来源；共用 NAT 出口不能仅凭 IP 区分员工。
- 白名单、开放状态、权限变化后，长连接每秒复查并取消。应用自身的 404、500 保留，不混同平台代理故障。
- 过滤平台会话 Cookie，阻止应用覆盖平台 Cookie；剥离应用设置的跨子域 Cookie 范围和 HSTS 等响应头。应用自身的认证可继续使用。
- 检查跨来源请求及 WebSocket。Cookie 不按端口隔离，多个带登录态的应用优先使用独立预览子域。

## 验证范围

正式回归包括 `backend/pkg/runtimeadapter/*preview*_test.go`、后台终端 Go/Python 测试、MCP 鉴权、浏览器 Origin、前端任务控制、安装器配置和回滚测试。数据库测试使用独立 PostgreSQL，不以跳过后的通过结果代替验收。

实机发布验收另外检查三执行器真实工具调用、重复请求、日志、精确停止、回合结束后持续运行、HTTP/WS/流式代理、白名单与连接撤销、四种地址组合、在线及断网离线安装、重配置失败恢复。使用专用任务和临时资源，分别记录模拟、真实网络、模型调用和浏览器结果；不在仓库保留一次性凭证或过程脚本。
