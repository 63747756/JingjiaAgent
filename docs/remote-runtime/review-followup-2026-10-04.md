## 本轮修复

1. 公开 restart 使用白名单请求，只接受 `request_id` 与 `load_session`。任务 ID、日志存储和内部业务变更由服务端控制；内部 mutation JSON 持久化仍保留。真实 WebSocket 分发测试覆盖 Restart/Resume 命中与未命中以及注入资源、模型、执行配置等场景。
2. OpenCode 订阅 reset 前发布已取得的可信前缀；首次 gap 后整个 Run 只以完整快照单调补齐，不再将无法确定位置的 delta 叠加到旧快照。正常无 gap 的流式不变；断线后余下输出可能等文字块完成才显示。这解决已复现的组件级旧快照批次反例，不声称官方普通重连必然产生该反例。Guest 源码锁升至 p22，daemon 仍为 p17。
3. 长控制操作区分 pending 与终态。15 秒客户端等待到期只显示待确认，保留原 ID 和原选择；同连接 35 秒无响应或服务器 pending 后退避恢复。重连、刷新和返回页面按同账号/任务恢复原 ID；只保存白名单选择，不保存执行配置或凭据。明确终态、权限错误或不存在才清理，临时观测错误保持关联。

模型切换、资源切换、普通重启/清上下文与错误继续入口均接入待确认状态。重复点击不创建新请求，终态回调只执行一次。刷新恢复重启结果，不自动补发先前的“继续任务”消息。恢复返回的稀疏模型信息不会覆盖完整模型名称等已有字段。
